# Issue tracker: Local Markdown

No tracker: the tasks are the issues. Small work keeps them in `tasks/todo.md`; big work has a folder, `docs/work/<slug>/`, with its spec, plan and tickets.

## When a skill says "publish to the issue tracker"

Add a task to the active `todo.md`. For big work, add `issues/<NN>-<slug>.md` to its work folder, numbered from `01`, with a `Status:` line (`open`, `in-progress`, `done`) near the top. Items for later with no active work: leave them in the report or reply.

## When a skill says "fetch the relevant ticket"

Read the task or file the user names.
