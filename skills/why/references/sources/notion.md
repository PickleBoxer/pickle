# Long-form docs (Notion)

PRDs, specs, RFCs, ADRs, design review notes, postmortems and runbooks: the why written before it became code. Adapt for Confluence or Google Docs by reading the server's tools first.

## Search

1. Search by feature name, key symbols, the PR author, error strings and user-facing terms. Narrow by time when the ship date is known.
2. Fetch candidate pages in full. The rationale is often mid-document.
3. Follow child pages and backlinks: alternatives considered, appendices.
4. Search meeting notes and databases for the decision around the PR's dates.

## Good evidence

A "Problem" or "Motivation" section that matches the code, an "Alternatives considered" section, a postmortem that names the code as the fix, meeting notes recording "we decided X because Y" near the PR date.

## Pitfalls

- Specs often describe the plan, not what shipped. Flag where doc and code differ.
- Several drafts: find the final or latest one and give its date.
- A page you cannot open is a gap.

## Report per doc

Title and URL, authors and last-updated date, the motivation quoted with its section, linked pages, draft or final.
