# Issue tracker (Linear)

Where the product or business reason lives: "customer X asked", "for the compliance initiative". Adapt for Jira, GitHub Issues or Shortcut by reading the server's tools first.

## Search

1. Fetch every ticket ID from the code anchor first. Read the whole issue with its comments.
2. Search issues by feature name, key symbol and business term. Try several phrasings.
3. From a sub-issue, fetch its parent. Parents often carry the why.
4. Read the project and its attached docs (PRDs, specs).
5. Note labels (`customer-request`, `incident-followup`, `compliance`, `perf`) and milestones: they name the kind of motivation and the deadline.

## Pitfalls

- Scope drift: a ticket closed and reopened with a new scope. Read the history.
- Boilerplate "Why" sections ("improve user experience") are not an answer.
- Stale tickets describe a plan that changed. Compare dates with the ship date.
- Follow duplicate chains to the canonical ticket.
- An issue you cannot open is a gap, not a guess.

## Report per ticket

ID and title, the motivation quoted from the description or comments, labels, parent and project, author, created and closed dates, link.
